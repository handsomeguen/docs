# Feature Specification: 관리자 기능 보강

**Feature Branch**: `feature/admin-tools` (코드: handsomeguen/blogville `feature/admin-tools`, `develop` 대상)

**Created**: 2026-10-13

**Status**: Implemented

**Input**: 블로그·커뮤니티 관리 화면(티스토리, 네이버 카페, Discourse)처럼 관리자가 회원·콘텐츠·사이트를 한곳에서 관리하게 한다

**다루는 명세 요구사항**: AUTH-08 관리자의 하위 항목 **ADM-01~07** (새 영역을 만들지 않고 4.1 AUTH-08 아래에 둔다. 관리자 기능은 모두 AUTH-08의 같은 사용자·권한 규칙(`requireAdmin`, 아니면 404)을 따르기 때문이다). ADM-01 회원 관리, ADM-02 콘텐츠 관리, ADM-03 통계, ADM-04 사이트 공지 띠, ADM-05 금지어, ADM-06 관리 기록, ADM-07 관리자 탭·막기.

**명세와 다른 점**: 명세에 없던 기능이다 (AUTH-08 열린 질문의 "회원 정지"와 "관리자를 여러 명 둘까?"에 답한다). 글 블라인드(관리자가 글을 비공개로 잠금)를 함께 넣었다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 관리자 탭 (ADM-07, Priority: P1) 🎯

1. 모든 관리자 화면 위에 탭: `📊 대시보드`(`/admin`) · `👥 회원`(`/admin/members`) · `📝 콘텐츠`(`/admin/content`) · `🐞 버그·문의`(`/admin/feedback`) · `⚙️ 사이트 설정`(`/admin/settings`, 공지 띠·금지어) · `📜 관리 기록`(`/admin/audit`). 지금 화면의 탭은 진하게(`aria-current="page"`). 좁은 화면에서는 탭 줄만 옆으로 밀리고 화면은 가로로 넘치지 않는다.
2. 방문자·일반 회원은 모든 관리자 화면이 404 (레이아웃과 화면 모두 `requireAdmin`). 관리자 Server Action도 첫 줄이 `requireAdmin`이라 조작한 요청은 404로 끝나고 아무것도 바꾸지 않는다.
3. 입력은 모두 서버가 다시 본다: 회원 ID(zod 1~64자), 글·댓글 ID(`parseId`), 정지 기간·사유·역할·탭·항목·공지·금지어는 `src/lib/admin-rules.ts`의 순수 함수.

### User Story 2 - 회원 관리 (ADM-01, Priority: P1)

1. `/admin/members`: 아이디·닉네임 일부로 찾기(`?q=`, 50자까지, `%`·`_`는 글자 그대로), `전체`·`정지된 회원`·`관리자` 거르기, 가입 최신순 20명씩. 줄마다 아이디·닉네임·블로그 링크·👑 관리자·🚫 정지·글 수·가입·마지막 접속, 정지 중이면 정지 문구.
2. 내 줄에는 [관리]가 없고 `내 계정이에요. 내 권한은 다른 관리자만 바꿀 수 있어요.`
3. [관리]를 펴면:
   - **정지** (회원만): 기간 `1일`·`7일`(기본)·`30일`·`영구` + 사유(1~200자, 회원에게 보임) → 확인 창 → 정지. 그 회원의 세션을 모두 지워 바로 로그아웃된다.
   - **정지 풀기**: 확인 창 → 해제.
   - **관리자 지정 / 관리자 해제**: 확인 창. 지정하면 정지도 풀린다. 바뀐 권한은 다음 요청부터 바로 쓰인다.
   - **비밀번호 초기화** (회원만, 기존 AUTH-07 열린 질문 기능).
   - **강제 탈퇴** (회원만): 확인 창 `{아이디} 님을 강제 탈퇴시킬까요? 블로그·글·방명록이 모두 지워지고 되돌릴 수 없어요.` → 회원 탈퇴(AUTH-06)와 같은 정리(`deleteMember`: 댓글 자리 남기기, 로그인 실패 기록, CASCADE).
4. 막는 규칙 (서버, 조작해도 같다):
   - 나 자신은 정지·강제 탈퇴·역할 변경 모두 `내 계정에는 할 수 없어요`.
   - 다른 관리자는 정지·강제 탈퇴 `관리자에게는 할 수 없어요. 먼저 관리자 권한을 빼 주세요`.
   - 마지막 관리자는 해제할 수 없다 `관리자가 한 명은 있어야 해요` (관리자 행을 모두 잠그고 센다. 내 역할을 바꿀 수 없으므로 화면에서는 생기지 않고, 동시에 서로를 해제할 때 지킨다).
   - 사유가 없거나 200자를 넘으면 `사유를 1~200자로 적어 주세요`, 고를 수 없는 기간은 `정지 기간을 골라 주세요`.

**정지된 회원의 로그인**
- 아이디 로그인: 비밀번호가 맞아도 `이용이 정지된 계정이에요 (2026. 10. 20. 15:00까지, 사유: 도배)` (한국 시간). 영구는 `이용이 정지된 계정이에요 (영구 정지, 사유: 도배)`. 비밀번호가 틀리면 지금처럼 `아이디 또는 비밀번호가 맞지 않아요` (정지 여부를 알려 주지 않는다). 정지 문구가 나오면 로그인 실패 수는 지운다.
- 세션을 만드는 곳(`databaseHooks.session.create.before`)에서 거절하므로 소셜 로그인도 막힌다 (첫 화면 `이용이 정지된 계정이에요.`).
- 정지 중에 세션이 남아 있어도(예: 정지와 로그인이 겹침) 요청마다 회원 행을 함께 읽어(`getSession`) 그 세션을 지우고 로그인하지 않은 것으로 본다. 그래서 정지된 회원은 글·댓글·방명록·문의 등 어떤 쓰기도 할 수 없다.
- 기간이 지나면 저절로 풀린다 (`suspended_until > now()`일 때만 정지).

### User Story 3 - 콘텐츠 관리 (ADM-02, Priority: P1)

1. `/admin/content` 탭 `글` / `댓글·답글` / `방명록` (`?tab=posts|comments|guestbook`), 최신순 20개씩.
   - 글: 제목(공개 글만 링크, 비공개 글은 관리자에게도 404라 글자만), 공개/🔒 비공개, 🚫 블라인드, 본문 앞부분, 작성자(닉네임·아이디), 블로그 링크, 작성 시각.
   - 댓글·답글: 지우지 않은 것만. 종류, 🔒 비밀이어도 **내용을 보인다**(관리자는 비밀 댓글을 볼 수 있다, specs/055), 작성자(탈퇴하면 `탈퇴한 회원`), 글 제목(공개 글이면 `/@주소/글ID#comments` 링크), 시각.
   - 방명록: 🔒 비밀이어도 내용, 주인 답글 앞부분, 작성자, `{블로그} 방명록` 링크, 시각.
2. 줄마다 선택 상자, 위에 `이 쪽 모두 선택`과 [선택 삭제]. 고르지 않고 누르면 `지울 항목을 골라 주세요`. 고르면 확인 창 `선택한 N개를 삭제할까요? 되돌릴 수 없어요.` → `N개를 삭제했어요` (이미 지워진 것은 `(이미 지워진 M개는 건너뜀)`).
3. 지우는 방식은 기존과 같다: 글은 행 삭제(댓글·공감·첨부 연결 CASCADE), 댓글·답글은 내용을 비우고 자리만 남김(`삭제된 댓글이에요`, SOC-01), 방명록은 행 삭제(답글 함께, BLOG-10).
4. 한 번에 50개까지, 탭과 맞지 않는 종류나 이상한 ID가 섞이면 아무것도 지우지 않는다(`요청이 올바르지 않아요`).
5. **글 블라인드**: 글 줄의 [블라인드]를 펴 사유(1~200자)를 적고 [가리기] → 확인 창 → 글이 비공개가 되고 작성자는 다시 공개할 수 없다(고쳐 저장해도 비공개, 공개 전환도 안 됨, DB CHECK `posts_blinded_private`). 작성자에게는 글 화면·수정 화면 위에 `🚫 관리자가 가린 글이에요 (사유: …)`. [블라인드 해제] → 잠금만 풀려 글은 비공개로 남고 작성자가 다시 공개할 수 있다.

### User Story 4 - 통계 (ADM-03, Priority: P2)

1. `/admin` 대시보드의 기존 통계 카드 4개·버그·문의·회원 찾기·최근 가입·최근 글은 그대로.
2. `📈 최근 7일 활동` (기간 [7일]·[30일], `?range=30`): 가입자 · 글 · 댓글·답글 · 블로그 방문을 한국 날짜별 막대 4개와 합계로. 막대는 CSS로만 그린다(새 라이브러리 없음). 화면 읽기 프로그램은 막대마다 `10월 13일 3명`을 읽는다. 지운 글·댓글은 세지 않는다. 방문은 `blog_visits`(같은 브라우저 하루 1번, BLOG-06).
3. 아래에 지금 정지된 회원 수(누르면 `정지된 회원` 거르기)와 블라인드 글 수.
4. `🏆 최근 30일 방문 많은 블로그`: 오늘 포함 30일 방문 수 상위 10개(블로그 이름 링크, 주인 닉네임, 방문 N회). 없으면 `방문 기록이 없어요`.

### User Story 5 - 사이트 공지 띠 (ADM-04, Priority: P2)

1. `/admin/settings`의 `📢 공지 띠`: 공지 문구(1~200자, 공백은 하나로), 링크(선택, 이 사이트 안의 `/…` 주소만, 200자까지, `safeNext`), [모든 화면 위에 보이기], [공지 띠 저장] → `공지 띠를 저장했어요` (끄면 `공지 띠를 저장했어요 (꺼 둠)`). 밖 주소는 `링크는 이 사이트 안의 주소(/로 시작)만 쓸 수 있어요`.
2. 켜 두면 모든 화면의 헤더 위에 노란 한 줄 `📢 {문구}` (링크가 있으면 문구가 링크)와 [✕ 공지 닫기]. PC 마을 화면에는 헤더·아래 막대처럼 보이지 않는다(CSS `body:has([data-town]) > .site-notice`). 휴대폰 마을에는 보인다.
3. [✕]를 누르면 이 브라우저에 기억해(`localStorage` `bv-notice-dismissed:{저장 시각}`) 다시 보이지 않는다. 관리자가 공지를 다시 저장하면(저장 시각이 바뀌면) 닫았던 브라우저에도 또 보인다. 저장소를 쓸 수 없는 브라우저는 닫기를 기억하지 못할 뿐 공지는 보인다. 닫았는지는 브라우저만 알므로 화면이 준비된 뒤에 나타난다(닫은 공지가 깜빡이지 않게).
4. 공지를 읽지 못해도(DB 오류) 화면은 열린다.

### User Story 6 - 금지어 (ADM-05, Priority: P2)

1. `/admin/settings`의 `🚫 금지어`: 한 줄에 하나(앞뒤 공백 무시, 빈 줄·대소문자만 다른 중복은 뺌), 한 줄 1~30자, 200개까지. 넘으면 `금지어는 한 줄에 1~30자로 적어 주세요: …`·`금지어는 200개까지 등록할 수 있어요`. [금지어 저장] → `금지어 N개를 저장했어요`.
2. 저장할 때 금지어가 들어 있으면(대소문자 무시, 글자 안에 들어 있기만 해도) `사용할 수 없는 말이 들어 있어요: {단어}`로 거절하고 쓴 내용은 남는다:
   - 글 쓰기·고치기: 제목과 본문 글자(`content_text`, 그림·태그 제외)
   - 댓글·답글 쓰기·고치기
   - 방명록 쓰기·고치기, 주인 답글
   - 버그·문의 보내기: 제목과 내용
3. 관리자도 같다. 이미 저장된 글은 바꾸지 않는다(고쳐 저장할 때 막는다).
4. 서버는 금지어 목록을 30초 동안 기억한다. 관리자가 저장하면 그 서버의 기억은 바로 지운다(서버가 여러 대면 다른 서버는 30초 안에 따라온다).

### User Story 7 - 관리 기록 (ADM-06, Priority: P2)

1. 관리자가 한 일은 모두 `admin_audit`에 남는다(바꾸는 일과 같은 트랜잭션인 것은 함께 남거나 함께 사라진다): 회원 정지(기간·사유) · 정지 해제 · 관리자 지정 · 관리자 해제 · 강제 탈퇴 · 비밀번호 초기화(임시 비밀번호는 남기지 않음) · 글 삭제(`/admin` 최근 글, 글 화면, 콘텐츠 관리 모두) · 댓글 삭제 · 답글 삭제 · 방명록 삭제 · 글 블라인드(사유) · 블라인드 해제 · 공지 띠 변경(켬/끔, 문구·링크) · 금지어 변경(추가·삭제 단어) · 문의 답변(상태·답변 앞부분).
2. `/admin/audit`: 최신순 20개씩, 줄마다 종류 · 대상(아이디·글 제목·내용 앞부분) · `by {관리자 아이디}`(탈퇴한 관리자면 `(탈퇴한 관리자)`) · 시각 · 자세히. `종류` 고르기 + [거르기](`?action=suspend`).
3. 대상이 지워져도 기록은 남는다(대상 이름을 글자로 남긴다).
- 글 화면에서 관리자가 남의 댓글·답글·방명록을 지우는 것(SOC-01·BLOG-10의 기존 관리자 권한)은 기록하지 않는다. 콘텐츠 관리에서 지울 때만 남는다 (열린 질문).

### 화면

- 375px에서 모든 관리자 화면에 가로 스크롤이 없고, 버튼·선택 상자의 누르는 영역은 44px 이상이다.

## Success Criteria *(mandatory)*

- **SC-001**: `tests/unit/admin-rules.test.ts`(정지 기간·문구, 역할·탈퇴 막기, 선택 항목, 공지 띠, 금지어, 통계 날짜, 기록 종류)와 `tests/e2e/admin-tools.spec.ts` 12개가 통과하고, 관리자·비밀번호 초기화·버그·문의·방명록·댓글·비밀 댓글·글·탈퇴·로그인·알림·업데이트 소식·마을·휴대폰 시험이 그대로 통과한다.
