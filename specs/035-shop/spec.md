# Feature Specification: 마을 상점

**Feature Branch**: `035-shop`

**Created**: 2026-10-12

**Status**: Implemented

**Input**: User description: "계속 모든 작업이 끝날 때까지 쭉 진행해줘" (034 다음 게임 순서)

**다루는 명세 요구사항**: SHOP-01 아이템 구매(구역·카드·버튼 상태·정렬 6가지·산 뒤 안내), SHOP-02 레벨 제한, SHOP-03 코인 부족과 음수 방지, GAME-06 레벨업 팝업의 [상점 가기]와 새 아이템 줄, ERD 3.6 `items`·`user_items`·원장 `purchase`.

**명세와 다른 점**:
- 파는 것은 아바타 꾸미기 9개(모자·옷·소품, 상점 표의 SHOP-06 줄), 가구 6개, 배경 5개다. 옷가게(SHOP-08)·미용실(SHOP-07)·성장 아이템(동물 농장이 없어서)·광장 장식은 아직 없어 구역은 `👕 아바타 꾸미기` · `🪑 가구` · `🖼 배경` 셋이다.
- 그림은 사용자 결정 "단순 도트"대로 16×16 글자 칸(`src/lib/art/items.ts`). 모자·옷·소품은 회색 마네킹 위에 겹쳐 그린다.
- 꾸미기(`/closet`)와 우리 집이 다음 단계라 산 뒤 안내는 링크 없이 `꾸미기에서 장착할 수 있어요` / `내 블로그의 우리 집에 놓을 수 있어요`로 끝난다. 그 화면이 생기면 링크를 붙인다. 기본 아이템(초원·화분·의자)도 그때 넣는다.
- 광장이 없어 입구는 헤더 `🏪 상점`(넓은 화면에서만 글자)과 레벨업 팝업 [상점 가기], 내역 화면 아래 링크다. 헤더가 길어져 `📮 출석`도 넓은 화면에서만 글자를 보인다.
- 원장 `purchase`는 같은 아이템에 한 번만(부분 고유 인덱스 `point_ledger_purchase_uq`), 구매만 코인이 줄고 경험치가 없다(CHECK).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 사기 (Priority: P1) 🎯

1. `/shop` `🏪 마을 상점`: 안내, `Lv.N 🪙 N` 카드, 정렬, 세 구역. 카드는 그림·이름·설명·`🪙 가격`·`Lv.N+`(2 이상)·버튼.
2. 버튼: 보유 중 → 🔒 Lv.N → 코인 부족 → 사기. 사는 동안에는 모든 버튼을 잠근다.
3. 서버는 한 트랜잭션에서 [회원 행 KEY SHARE → 회원 잠금 → 판매 아이템 → 보유 → 그 순간의 레벨·잔액 → `user_items` → 원장 `purchase` −가격]. 오류 문구 `살 수 없는 아이템이에요` / `이미 가지고 있는 아이템이에요` / `레벨 N부터 살 수 있어요` / `코인이 N개 부족해요`.
4. 성공하면 화면 위에 붙는 안내 `🎉 {이름}을/를 샀어요! …`, 헤더 코인이 줄고, 내역에 `🏪 상점 구매 🪙 −N`.

### User Story 2 - 정렬 (Priority: P2)

레벨순(기본)·인기순·비싼 순·싼 순·최신순·보유순, 모두 마지막은 ID 순. 이 화면에서만 유지.

### User Story 3 - 레벨업 팝업 (Priority: P2)

[상점 가기]는 `/shop`. 안 읽은 가장 낮은~높은 레벨에서 열린 판매 아이템을 필요 레벨 높은 순 → ID 순으로 3개까지 `이제 이런 친구를 데려올 수 있어요`와 그림(64px)·이름, 더 있으면 `외 N개`.
