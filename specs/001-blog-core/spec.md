## User Scenarios & Testing *(mandatory)*

### User Story 1 - 가입하면 바로 내 블로그가 생긴다 (Priority: P1)

방문자가 첫 화면에서 아이디·비밀번호·블로그 이름만 적고 가입하면, 따로 로그인하거나 블로그를 만드는 단계 없이 내 블로그(`/@아이디`)에 도착한다. 이후 로그인·로그아웃할 수 있다.

**Why this priority**: 모든 기능의 시작점이다. 블로그가 없으면 글을 쓸 곳이 없다.

**Independent Test**: 빈 DB에서 가입 → `/@아이디`에 환영 문구와 빈 글 목록이 보이고, 로그아웃 → 로그인하면 다시 내 블로그로 간다.

**Acceptance Scenarios**:

1. **Given** 로그인하지 않은 방문자, **When** `Tester1` / 비밀번호 8자 이상 / 블로그 이름을 비워 둔 채(자동으로 `tester1의 블로그`) 가입하면, **Then** 아이디 `tester1`, 닉네임 `tester1`, 블로그 `/@tester1`·이름 `tester1의 블로그`·빈 소개, 대분류 카테고리 "일상" 1개가 생기고 `/@tester1?welcome=1`에서 환영 문구가 보인다.
2. **Given** 가입 폼, **When** 아이디를 적으면, **Then** 블로그 이름 칸이 `{아이디}의 블로그`로 따라 채워지고, 회원이 이름을 고친 뒤에는 아이디를 바꿔도 따라가지 않으며, 칸을 비우면 다시 따라간다.
3. **Given** 이미 `tester1`이 있음, **When** `TESTER1`로 가입하거나 다른 회원의 블로그 주소·닉네임과 같은 아이디로 가입하면, **Then** `이미 있는 아이디예요`가 보이고 회원이 생기지 않는다.
4. **Given** 가입 처리 중 블로그 만들기가 실패함, **When** 가입을 보내면, **Then** 회원·프로필·블로그·카테고리 어느 것도 남지 않는다.
5. **Given** 같은 아이디로 거의 동시에 두 번 가입, **Then** 회원은 1명만 생긴다.
6. **Given** 가입한 회원, **When** 로그아웃하면, **Then** 확인 창 없이 세션·쿠키가 지워지고 첫 화면으로 가며, 회원 화면(`/write`)에 들어가면 첫 화면으로 보내진다.
7. **Given** 가입한 회원, **When** 첫 화면에서 맞는 아이디(대소문자·앞뒤 공백 무시)와 비밀번호로 로그인하면, **Then** 내 블로그로 간다.
8. **Given** 같은 아이디로 5번 연속 로그인 실패, **When** 6번째에 맞는 비밀번호를 넣으면, **Then** `로그인을 너무 많이 시도했어요. 5분 뒤에 다시 시도해 주세요`가 보인다.
9. **Given** [로그인 상태 유지]를 고르지 않고 로그인, **Then** 쿠키는 만료 없는 쿠키이고 마지막 사용 2시간 뒤 로그아웃된다. 고르면 7일 쿠키다.

### User Story 2 - 글을 쓰고 발행해서 읽는다 (Priority: P1) 🎯

회원이 에디터(제목, 굵게, 목록, 인용, 코드 블록, 링크)로 글을 쓰고 공개 또는 비공개로 발행한다. 발행하면 글 상세(`/@주소/글ID`)로 가고, 고치거나 지울 수 있다.

**Why this priority**: 블로그의 핵심 가치다. US1과 합치면 가장 작은 쓸모 있는 블로그(MVP)가 된다.

**Independent Test**: 로그인한 회원이 `/write`에서 글을 발행 → 상세에서 제목·본문이 보임 → [수정]으로 고침 → [삭제]하면 내 블로그 홈으로 가고 글이 없다. 다른 브라우저(방문자)로 비공개 글 주소를 열면 404.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원, **When** `/write`에서 제목과 본문을 쓰고 [발행하기]를 누르면, **Then** 글이 저장되고 `/@내주소/새글ID`로 가서 제목·본문·작성 시각이 보인다.
2. **Given** 줄 맨 앞에 `## `, `> `, `- `, ` ``` `를 입력, **Then** 큰 제목·인용·목록·코드 블록으로 바뀐다 (Tiptap 입력 규칙).
3. **Given** 본문에 `<script>`, `onerror`, `javascript:` 링크, `<iframe>`, `<style>`이 들어간 HTML을 조작해 보냄, **Then** 저장된 본문에는 그것들이 없다. 링크에는 `target="_blank" rel="noopener noreferrer nofollow"`가 붙는다.
4. **Given** 제목이 비었거나 공백뿐, **Then** `제목을 적어 주세요`. 본문 글자가 없으면 `본문을 적어 주세요`. 오류가 나도 제목·본문·카테고리·공개 설정은 그대로 남는다.
5. **Given** 내 글 상세, **When** [수정] → 내용을 바꿔 [수정 완료], **Then** 바뀐 내용이 보이고 수정 시각이 갱신된다.
6. **Given** 내 글 상세, **When** [삭제] → 확인 창에서 확인, **Then** 글이 지워지고 내 블로그 홈으로 간다.
7. **Given** 비공개로 발행한 글, **Then** 주인에게는 상세·목록에 `🔒 비공개`가 보이고, 다른 사람(방문자·다른 회원)이 주소를 열면 404 `길을 잃었어요`이다.
8. **Given** 남의 글, **When** `/write/남의글ID`로 들어가거나 수정·삭제 요청을 조작해 보내면, **Then** 404이거나 아무것도 바뀌지 않는다.
9. **Given** 로그인하지 않은 방문자, **When** `/write`에 들어가면, **Then** 첫 화면으로 보내진다.

### User Story 3 - 블로그 홈에서 글 목록을 넘겨 본다 (Priority: P2)

누구나 `/@주소`에서 그 블로그의 글을 최신순 8개씩 카드로 보고, 페이지 번호로 넘기고, 왼쪽 카테고리를 눌러 거른다.

**Why this priority**: 글이 몇 개만 쌓여도 목록과 페이지가 필요하다. 글 상세만으로는 블로그를 둘러볼 수 없다.

**Independent Test**: 시드로 글 9개를 넣은 블로그에서 1페이지 8개·2페이지 1개, `?page=abc`는 1페이지, 카테고리를 누르면 그 글만 보인다.

**Acceptance Scenarios**:

1. **Given** 공개 글 9개, **When** `/@주소`를 열면, **Then** 최신순 8개 카드(카테고리 배지·제목·본문 요약·날짜)와 페이지 번호 `1 2`가 보인다.
2. **Given** `?page=` 값이 `0`, `-1`, `abc`, `2.5`, `012`, `1e1`, `99999999999999999999`, **Then** 1페이지를 보여준다.
3. **Given** 글이 없는 블로그, **Then** 빈 화면 문구가 보이고 페이지 번호는 숨긴다. 주인에게는 [✏️ 첫 글 쓰기] 버튼이 함께 보인다.
4. **Given** 카테고리 "여행 › 맛집"이 있는 블로그, **When** 왼쪽 목록에서 "여행"을 누르면(`?category=ID`), **Then** 대분류가 여행인 글(소분류 포함)만, "맛집"을 누르면(`?category=ID&sub=ID`) 그 소분류 글만 보인다. 카테고리마다 글 수가 보인다.
5. **Given** 남의 블로그, **Then** 비공개 글은 목록·글 수에 들어가지 않는다. 주인에게는 비공개 글도 `🔒`와 함께 보인다.
6. **Given** 없는 주소(`/@nobody_here`), 대문자 주소(`/@NOTICE`), 다른 블로그의 글 ID, 숫자가 아닌 글 ID, **Then** 404 `길을 잃었어요`.

### User Story 4 - 카테고리를 2단계로 만들고 글에 붙인다 (Priority: P2)

블로그 주인이 블로그 관리(`/settings/blog`)에서 대분류·소분류를 추가·이름 바꾸기·순서 바꾸기·삭제하고, 글쓰기에서 대분류(+소분류)를 고른다.

**Why this priority**: 티스토리형 블로그의 기본 정리 수단이다. 없어도 글은 쓸 수 있어 P2.

**Independent Test**: "여행" 대분류 + "맛집" 소분류를 만들고 글에 붙이면 상세 배지가 `여행 › 맛집`. 소분류를 지우면 배지가 `여행`, 대분류를 지우면 배지가 사라지고 글은 남는다.

**Acceptance Scenarios**:

1. **Given** 블로그 관리 화면, **When** 이름을 적고 [추가](또는 Enter), **Then** 대분류가 맨 아래에 생긴다. 대분류 줄의 [소분류 추가]로 그 아래 소분류가 생긴다.
2. **Given** 이름이 비었거나 20자 초과, 또는 같은 블로그에 같은 대분류 이름(같은 대분류 안에 같은 소분류 이름), **Then** 각각 `카테고리 이름을 적어 주세요` / `카테고리 이름은 20자까지예요` / `이미 있는 카테고리예요`이고 적은 이름이 칸에 남는다.
3. **Given** 대분류 3개, **When** 가운데 것의 ▲를 누르면, **Then** 맨 위로 올라간다. 맨 위 ▲와 맨 아래 ▼는 비활성. 소분류는 같은 대분류 안에서만 움직인다.
4. **Given** [이름 바꾸기] → [저장], **Then** 그 카테고리의 글 배지가 새 이름으로 보인다.
5. **Given** 소분류 "맛집"에 글이 있음, **When** "맛집" 삭제 확인, **Then** 글은 "여행"에 남는다. **When** 대분류 "여행" 삭제 확인, **Then** 소분류도 지워지고 글은 "카테고리 없음"이 된다. 확인 창에서 취소하면 아무 일도 없다.
6. **Given** 글쓰기 화면, **When** 대분류를 고르면, **Then** 소분류 칸이 켜지고 그 대분류의 소분류만 나온다. 대분류를 바꾸면 고른 소분류가 풀린다.
7. **Given** 고른 대분류에 속하지 않는 소분류를 조작해 보냄, **Then** `잘못된 요청이에요`. 다른 블로그의 대분류 ID를 보내면 `카테고리 없음`으로 저장된다.

### User Story 5 - 블로그 이름·소개·주소와 닉네임을 바꾼다 (Priority: P3)

블로그 주인이 블로그 관리에서 이름(1~40자)·소개(0~160자)·주소(3~20자)를 바꾸고, 내 정보(`/settings/account`)에서 닉네임(2~20자)을 바꾼다.

**Why this priority**: 가입 때 기본값으로 시작할 수 있어 나중에 해도 된다.

**Independent Test**: 이름·소개를 바꾸면 블로그 홈 머리에 반영, 주소를 바꾸면 새 주소로 열리고 예전 주소는 404.

**Acceptance Scenarios**:

1. **Given** 블로그 관리, **When** 이름·소개를 고쳐 [저장], **Then** `저장했어요 ✓`가 보이고 블로그 홈에 반영된다.
2. **Given** 이름 공백뿐 / 41자 / 소개 161자, **Then** `블로그 이름을 적어 주세요` / `블로그 이름은 40자까지예요` / `소개는 160자까지예요`이고 칸에 보낸 값이 남는다.
3. **Given** 주소 칸, **When** `My_Blog`로 [주소 바꾸기], **Then** `my_blog`로 저장되고 `/@my_blog`로 열리며 예전 주소는 404다.
4. **Given** 주소가 형식 위반 / 예약어 / 다른 회원의 아이디·주소와 겹침, **Then** `주소는 영문 소문자, 숫자, _ 로 3~20자예요` / `이 주소는 쓸 수 없어요` / `이미 있는 주소예요`.
5. **Given** 내 정보, **When** 닉네임을 1자 / 21자 / 다른 회원의 아이디·닉네임으로 바꾸면, **Then** `닉네임은 2자 이상이에요` / `닉네임은 20자까지예요` / `이미 있는 닉네임이에요`.
6. **Given** 요청에 다른 회원의 `blogId`를 섞어 보냄, **Then** 내 블로그만 바뀐다.

### Edge Cases

- 가입 폼을 로그인한 채 보내면 내 블로그로 보낸다.
- 아이디가 예약어(`admin`, `api`, `write`, `settings`, `blog`, `notice`, `files`, `feed`, `tags`, `town` 등 명세 BLOG-02의 21개)면 `이 아이디는 쓸 수 없어요`.
- 비밀번호 8자 미만 / 64자 초과 / 확인 불일치 → `비밀번호는 8자 이상이에요` / `비밀번호는 64자까지예요` / `비밀번호가 서로 달라요`. 오류 뒤 비밀번호 칸만 비운다.
- 라이브러리 HTTP 가입·로그인·로그아웃 경로(`/api/auth/sign-up/*`, `/api/auth/sign-in/*`, `/api/auth/sign-out`)를 직접 부르면 404.
- 가입 FormData에 `role=admin`을 더해도 권한은 `user`.
- 글쓰기 중 세션이 만료되면 [발행하기]에서 첫 화면으로 가고 저장되지 않는다.
- 본문 HTML이 20만 자를 넘으면 `글이 너무 길어요`. UTF-8 900,000바이트를 넘으면 브라우저에서 미리 막는다.
- 글쓰기 화면을 연 뒤 고른 대분류가 다른 탭에서 지워지면 오류 없이 `카테고리 없음`으로 저장된다.
- 글 ID·카테고리 ID에 `0`, `abc`, `1.5`, `012`, `1e1`, `99999999999` → 화면 주소면 404, 폼 값이면 `잘못된 요청이에요`.
- 두 카테고리 순서 바꾸기 요청이 동시에 와도 순서가 꼬이지 않는다 (블로그 행 잠금).
- 다른 사이트 Origin으로 보낸 Server Action(로그아웃·글 삭제 등)은 거부되고 데이터가 그대로다.

## Requirements *(mandatory)*

### Functional Requirements

**회원 (AUTH)**

- **FR-001** (AUTH-07): 시스템은 아이디(영문 소문자·숫자·`_` 4~20자, 앞뒤 공백 제거·소문자로 저장), 비밀번호(8~64자), 비밀번호 확인, 블로그 이름(1~40자)으로 가입을 받아야 한다.
- **FR-002** (AUTH-07, BLOG-01): 가입은 한 트랜잭션으로 회원·아이디 로그인 수단(비밀번호 해시)·프로필(닉네임 = 아이디)·블로그(주소 = 아이디, 이름 = 적은 이름, 빈 소개)·대분류 "일상"을 만들어야 하고, 하나라도 실패하면 전부 취소해야 한다.
- **FR-003** (AUTH-03): 아이디·블로그 주소·닉네임은 다른 회원의 세 값 어느 것과도 겹칠 수 없다 (아이디·주소는 대소문자 무시). 같은 이름을 동시에 잡으려 하면 한쪽만 성공해야 한다.
- **FR-004** (AUTH-07): 가입에 성공하면 [로그인 상태 유지] 없이 로그인된 채 `/@아이디?welcome=1`로 가야 하고, 주인에게만 환영 문구를 보여야 한다.
- **FR-005** (AUTH-09): 회원은 아이디·비밀번호로 로그인할 수 있어야 한다. 없는 아이디와 틀린 비밀번호는 같은 문구 `아이디 또는 비밀번호가 맞지 않아요`를 보여야 한다. 성공하면 내 블로그로 간다.
- **FR-006** (AUTH-09, NF-11): 로그인 유지는 기본 "브라우저를 닫거나 2시간 쓰지 않으면 로그아웃", [로그인 상태 유지]면 7일이어야 한다. 쿠키는 HttpOnly·SameSite=Lax·(https) Secure.
- **FR-007** (NF-10): 같은 아이디로 5번 연속 실패하면 5분 동안 로그인을 막아야 한다 (없는 아이디도 똑같이 센다).
- **FR-008** (AUTH-04): 회원은 확인 창 없이 로그아웃할 수 있어야 하고, 세션 행과 쿠키가 지워진 뒤 첫 화면으로 가야 한다.
- **FR-009** (NF-12): 라이브러리 HTTP 인증 경로는 세션 조회 외에는 404여야 하고, 다른 Origin의 Server Action은 거부해야 한다.

**블로그 (BLOG)**

- **FR-010** (BLOG-01): 회원은 블로그를 정확히 하나 가진다. 블로그를 따로 만들거나 지우는 화면은 없다. DB가 두 번째 블로그를 거부해야 한다.
- **FR-011** (BLOG-02): 블로그 홈 주소는 `/@주소`, 글 상세는 `/@주소/글ID`여야 한다. 없는 주소·대문자 주소·다른 블로그의 글·형식이 틀린 글 ID·남의 비공개 글은 모두 같은 404 화면이어야 한다.
- **FR-012** (BLOG-03): 주인은 블로그 이름(1~40자)·소개(0~160자)·주소(3~20자, 예약어·겹침 불가)를, 내 정보에서 닉네임(2~20자)을 바꿀 수 있어야 한다. 길이는 앞뒤 공백 제거 뒤 코드 포인트로 센다. 주소를 바꾸면 예전 주소는 404다.
- **FR-013** (BLOG-05): 주인은 대분류와 그 아래 소분류(2단계까지)를 추가·이름 바꾸기·▲▼ 순서 바꾸기·삭제할 수 있어야 한다. 이름은 1~20자, 같은 단계 안에서 겹칠 수 없다 (글자 그대로 비교). 모든 변경은 버튼을 누르는 즉시 저장된다.
- **FR-014** (BLOG-05): 소분류를 지우면 그 글은 대분류에 남고, 대분류를 지우면 소분류도 지워지고 글은 "카테고리 없음"이 되어야 한다.
- **FR-015** (BLOG-05, POST-05): 블로그 홈 왼쪽에 대분류·소분류 목록과 각 글 수(보는 사람이 볼 수 있는 글만)를 보여야 한다.

**글 (POST)**

- **FR-016** (POST-01): 회원은 에디터(제목 H2·H3, 굵게, 기울임, 목록, 번호 목록, 인용, 코드 블록, 링크, 구분선)로 글을 작성·수정·삭제할 수 있어야 한다. 제목 1~100자, 본문 HTML 최대 200,000자, 정화 뒤 글자가 비면 저장하지 않는다.
- **FR-017** (POST-01, NF-03): 본문 HTML은 저장할 때 허용 태그(`p br h2 h3 strong em u s code pre blockquote ul ol li a hr`)만 남기고, 링크는 http·https·mailto·상대 주소만, `target="_blank" rel="noopener noreferrer nofollow"`를 붙여야 한다.
- **FR-018** (POST-01): 입력 규칙과 문구는 브라우저와 서버가 같은 모듈을 써야 하고, 오류는 정해진 순서로 하나만 보이며 입력값은 모두 남아야 한다.
- **FR-019** (POST-02): 글은 공개(기본)·비공개를 정할 수 있어야 한다. 비공개 글은 작성자에게만 보이고(`🔒 비공개` 표시), 다른 사람에게는 상세 404, 목록·글 수에서 빠져야 한다.
- **FR-020** (POST-03): 글에 대분류 하나(선택), 그 아래 소분류 하나(선택)를 지정할 수 있어야 한다. 서버는 대분류가 내 블로그 것인지, 소분류가 그 대분류 소속인지 확인해야 한다. 소분류만 있는 글은 없다.
- **FR-021** (POST-03): 목록 카드와 상세 제목 위에 카테고리 배지(`대분류` 또는 `대분류 › 소분류`)를 보여야 하고, 상세의 배지는 그 카테고리 목록으로 링크한다.
- **FR-022** (POST-05): 글 목록은 최신순(작성 시각, 같으면 ID 내림차순) 8개씩, `?page=N`(1~2147483647 정수, 아니면 1페이지) 페이지 번호로 보여야 한다.
- **FR-023** (NF-02): 글·카테고리·블로그 설정의 모든 쓰기는 서버에서 세션의 회원이 그 블로그 주인인지 확인해야 한다. 요청에 섞인 주인·블로그 ID는 무시한다.

**공통**

- **FR-024** (NF-19): 모든 오류 문구는 한국어로, 명세의 문구를 그대로 쓴다. 없는 화면은 `길을 잃었어요` 404, 서버 오류는 `잠깐 문제가 생겼어요` 화면과 [다시 시도].
- **FR-025** (NF-06, NF-18): 모든 화면은 375px에서 가로 스크롤이 없고 누르는 영역이 44px 이상이며, 키보드만으로 가입·로그인·글쓰기를 할 수 있어야 한다.

### Key Entities *(include if feature involves data)*

- **회원 (User)**: 아이디(유일, 소문자), 권한(`user`/`admin`), 가입 시각. 로그인 수단(Account: 비밀번호 해시)과 세션(Session: 유지 여부·만료)을 가진다.
- **로그인 시도 (LoginAttempt)**: 아이디별 연속 실패 수와 잠금 시각. 회원과 잇지 않는다 (없는 아이디도 센다).
- **프로필 (Profile)**: 회원 1명당 1개. 닉네임(2~20자, 유일).
- **블로그 (Blog)**: 회원 1명당 정확히 1개. 주소(유일), 이름(1~40자), 소개(0~160자).
- **대분류 (Category)**: 블로그에 속함. 이름(1~20자, 블로그 안에서 유일), 순서.
- **소분류 (Subcategory)**: 대분류에 속함. 이름(1~20자, 대분류 안에서 유일), 순서. 대분류가 지워지면 함께 지워진다.
- **글 (Post)**: 블로그에 속함. 제목, 정화한 본문 HTML, 본문 글자(요약용), 공개 여부, 대분류(선택)·소분류(선택), 작성·수정 시각.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 온 사람이 첫 화면에서 가입해 내 블로그에 도착하기까지 입력 칸 4개(아이디·비밀번호·확인·블로그 이름, 이름은 자동으로 채워짐), 1분 안에 끝난다.
- **SC-002**: 가입한 회원이 첫 글을 발행해 상세 화면을 보기까지 3번 이하의 클릭(✏️ 새 글 쓰기 → 발행하기)으로 끝난다.
- **SC-003**: 글이 1,000개 있는 블로그에서도 블로그 홈 글 목록이 데스크톱 첫 방문 1초 안에 보인다.
- **SC-004**: 위 5개 이야기의 수용 시나리오가 모두 자동 테스트(E2E 또는 단위)로 통과한다.
- **SC-005**: 남의 비공개 글·남의 글 수정·남의 카테고리 변경을 시도하는 조작 요청 중 성공하는 것이 0건이다.
- **SC-006**: 375px 휴대폰 화면에서 모든 화면에 가로 스크롤이 없다.

## Assumptions

- 명세의 게임 요소(기본 캐릭터 고르기, 가입 축하 코인, 출석, 우리 집, 마을 광장)는 이번에 만들지 않는다. 그래서 가입 폼에 캐릭터 칸이 없고, 가입·로그인 뒤 가는 곳은 광장(`/town`)이 아니라 내 블로그다. 첫 화면은 도트 마을 풍경 대신 간단한 소개 + 로그인·회원가입 탭이다.
- 비밀번호 찾기·변경은 명세에도 없어(AUTH-07 열린 질문) 이번에도 만들지 않는다.
- 이미지·파일 첨부가 없으므로 허용 태그에서 `img`와 파일 카드는 뺀다 (POST-07·09에서 추가).
- 임시 저장(POST-08)이 없으므로 세션 만료 때 쓰던 글은 보존하지 않는다.
- 관리자 계정·공지 블로그(`/@notice`)는 만들지 않지만, `notice`·`admin`은 예약어로 막아 둔다.
- 블로그 홈에는 명세 BLOG-08·09의 도구 막대·위젯 대신 주인에게 [✏️ 새 글 쓰기]·[⚙️ 블로그 관리] 두 버튼만 둔다.
- 시각은 한국 시간(Asia/Seoul)으로 표시한다.
