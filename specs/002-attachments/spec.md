# Feature Specification: 사진·파일 첨부

**Feature Branch**: `002-attachments`

**Created**: 2026-10-11

**Status**: Implemented

**Input**: User description: "다음 기능으로 사진·파일 첨부" (001-blog-core 다음 단계, 결정 카드에서 선택)

**다루는 명세 요구사항**: POST-07(이미지 첨부), POST-09(파일 첨부), POST-02(비공개 글의 첨부), NF-03(정화), NF-06(375px), NF-12(Origin 확인)

**이번에 하지 않는 것**: 프로필 사진(`profiles.photo_key`, 올리는 화면이 아직 없음), **내 다른 글의 첨부를 붙여 넣으면 새로 다시 올리기**(POST-07 흐름 7. 이번에는 이 글에 붙일 수 없는 첨부는 저장할 때 빠진다), 사진 대체 글 입력, 목록 썸네일, 정리 작업 자동 실행, 외부 저장소(S3 등).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 글에 사진을 넣는다 (Priority: P1) 🎯

회원이 글쓰기·수정 화면에서 [🖼 사진]으로 고르거나, 붙여 넣거나, 끌어다 놓아 사진을 여러 장 한 번에 넣는다. 발행하면 글 상세에서 사진이 본문 폭에 맞춰 보인다.

**Why this priority**: 티스토리형 블로그에서 사진을 못 넣는 것이 지금 가장 큰 빈자리다.

**Independent Test**: 로그인 → `/write`에서 [🖼 사진]으로 PNG 두 장 → 본문에 두 장 → 발행 → 상세에서 두 장이 보이고, 수정 화면에도 그대로 있다.

**Acceptance Scenarios**:

1. **Given** 글쓰기 화면, **When** [🖼 사진]으로 두 장을 한 번에 고르면, **Then** 두 장 모두 커서 자리에 올린 순서대로 들어가고, 올리는 동안 `올리는 중... (1/2)`이 보이며 발행 버튼은 `첨부를 올리는 중...`으로 막힌다.
2. **Given** 클립보드에 스크린샷, **When** 본문에 붙여 넣으면, **Then** 사진이 들어간다. 파일을 본문에 끌어다 놓으면 놓은 자리에 들어간다.
3. **Given** 사진이 든 글을 발행, **Then** 상세에서 사진이 보이고, 저장된 본문에는 `<img src="/files/키" alt="">`만 있고 `data:`가 없다. 사진은 글자 수(`content_text`)에 들어가지 않는다.
4. **Given** SVG, BMP 같은 형식, **Then** `파일이름: 올릴 수 없는 형식이에요. …`. 10MB 넘는 사진은 `사진은 10MB까지 올릴 수 있어요`. 빈 파일은 `빈 파일은 올릴 수 없어요`. 거부된 것은 본문에 들어가지 않고, 문제없는 사진은 들어간다. 문구는 [✕]로 닫는다.
5. **Given** 브라우저 확인을 건너뛰고 직접 요청, **Then** 다른 사이트 Origin·`Origin` 없음은 403, 로그인 안 함은 401, `Content-Length` 없음은 411, 확장자만 `.png`인 SVG·HTML은 415다.
6. **Given** 사진만 있고 글자가 없는 본문, **Then** `본문을 적어 주세요`.
7. **Given** 375px 화면, **Then** 큰 사진이 든 글도 가로 스크롤이 없다.

### User Story 2 - 글에 파일을 붙이고 원래 이름으로 내려받는다 (Priority: P2)

회원이 [📎 파일]로 PDF·한글·오피스·ZIP 등을 넣으면 본문에 파일 카드(아이콘, 원래 이름, 크기, 내려받기)가 들어간다. 읽는 사람은 카드를 눌러 원래 이름으로 내려받는다.

**Independent Test**: `보고서 최종본.pdf`를 [📎 파일]로 넣고 발행 → 상세 카드에 이름·크기 → 누르면 `보고서 최종본.pdf`로 같은 내용이 내려받아진다.

**Acceptance Scenarios**:

1. **Given** PDF와 HWP를 한 번에 끌어다 놓음, **Then** 파일 카드 두 개가 들어간다.
2. **Given** 발행한 글의 파일 카드, **Then** `원래 이름` / `1.2MB · 내려받기`가 보이고, 누르면 한글·괄호·따옴표가 든 이름도 그대로 내려받는다.
3. **Given** EXE·HTML, **Then** `올릴 수 없는 형식이에요…`(서버도 415). 30MB 넘는 파일은 `파일은 30MB까지 올릴 수 있어요`(서버도 413).
4. **Given** 파일 카드의 이름·크기를 조작해 보냄, **Then** 저장할 때 처음 올린 이름·크기로 바뀐다.
5. **Given** [📎 파일]로 사진을 고름, **Then** 사진으로 들어간다.
6. **Given** 파일 카드, **Then** 글자 수에 들어가지 않고, 수정 화면을 열면 그대로 있다.

### User Story 3 - 볼 수 있는 사람만 첨부를 연다 (Priority: P1)

첨부는 붙은 글의 공개 설정을 따른다. 아직 어느 글에도 붙지 않은 첨부는 올린 사람만 연다.

**Independent Test**: 회원 A가 사진을 올림(저장 전) → 방문자·회원 B는 404 → A가 공개 글로 발행 → 방문자도 열림 → 비공개로 바꿈 → 방문자 404, A는 열림.

**Acceptance Scenarios**:

1. **Given** 올리기만 하고 저장하지 않은 첨부, **Then** 올린 사람만 열고 다른 회원·방문자는 404 `파일을 찾을 수 없어요`.
2. **Given** 공개 글의 첨부, **Then** 누구나 열고, 머리글은 실제 형식·`nosniff`·`Cache-Control: private, no-cache`·`ETag: "키"`다. `If-None-Match`로 다시 요청하면 304, 권한이 없으면 404.
3. **Given** 비공개 글의 첨부, **Then** 블로그 주인만 연다.
4. **Given** 본문에 다른 사이트 주소·`data:`·없는 키·남의 첨부·다른 글에 붙은 첨부를 섞어 보냄, **Then** 저장할 때 빠지고, 원래 글의 첨부는 그대로다.
5. **Given** 본문에서 사진을 지우고 저장하거나 글을 지움, **Then** 그 첨부는 글에서 떨어지고(`detached_at`) 방문자는 열 수 없다. 올린 사람은 하루 동안 다시 붙일 수 있다.

### User Story 4 - 쓰이지 않는 파일을 정리한다 (Priority: P3)

운영자가 `npm run posts:cleanup`을 돌리면 어느 글에도 붙지 않은 지 하루가 지난 첨부와, DB 행이 없는 저장소 파일(1시간 지난 것)을 지운다.

**Acceptance Scenarios**:

1. **Given** 하루 지난 붙지 않은 첨부, 최근에 떨어진 첨부, 붙어 있는 첨부, **When** 정리 작업, **Then** 첫 번째만 행과 파일이 지워지고 `지운 첨부: 1개`가 출력된다.
2. **Given** `-- --dry-run`, **Then** 세기만 하고 지우지 않는다.

### Edge Cases

- 올리는 중에 또 붙여 넣거나 끌어다 놓으면 넣지 않고 `다른 파일을 올리는 중이에요. 끝난 뒤 다시 넣어 주세요`.
- 에디터 밖에 파일을 떨어뜨리면 아무 일도 없다 (브라우저가 그 파일을 열어 쓰던 글을 잃지 않게).
- 글자와 그림을 함께 복사해 붙여 넣으면(엑셀 등) 글자만 붙여 넣는다.
- 다른 사이트 사진이 든 HTML을 붙여 넣으면 에디터에 그 사진이 들어가지 않는다.
- 내 다른 글의 `/files/키`를 붙여 넣으면 에디터에는 보이지만 저장할 때 빠진다 (다시 올리기는 다음 단계).
- 회원을 지우면 첨부 행은 지워지고 파일은 정리 작업의 "주인 없는 파일"이 지운다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001** (POST-07): 사진 형식은 PNG·JPG·GIF·WEBP, 한 장 10MB까지. 서버는 확장자와 파일 앞부분(매직 넘버)이 맞는지 확인한다. SVG는 받지 않는다.
- **FR-002** (POST-09): 파일 형식은 PDF·HWP·HWPX·DOC·DOCX·XLS·XLSX·PPT·PPTX·KEY·ZIP·TXT·CSV·MD·JSON·MP3·MP4, 한 개 30MB까지. 응답 형식은 서버의 확장자 표로 정한다 (브라우저가 알려 준 형식은 믿지 않는다).
- **FR-003**: 올리기 `POST /api/uploads`는 Origin을 이 사이트 주소와 비교(403), 로그인 확인(401), `Content-Length` 없음(411)·31MB 초과(413)를 본문을 읽기 전에 거절한다.
- **FR-004**: 저장 이름은 서버가 만든 무작위 32자 16진수다. 원래 이름은 경로·제어 문자를 빼고 255자까지로 줄여 DB에만 둔다.
- **FR-005**: 글을 저장하면 본문의 첨부 중 **내가 올렸고, 어느 글에도 붙지 않았거나 이 글에 붙은 것**만 남기고 이 글에 붙인다. 이 글에 붙어 있다가 빠진 첨부는 떨어진다. 한 첨부는 한 글에만 붙는다.
- **FR-006**: 정화는 `img`를 `/files/키`이고 이 글에 붙일 수 있는 `image` 첨부일 때만, 파일 카드(`a[data-file]`)를 붙일 수 있는 `file` 첨부일 때만 남기고, 카드의 이름·크기 속성은 DB 값으로 다시 쓴다.
- **FR-007**: `GET /files/[키]`는 공개 글: 누구나 / 비공개 글: 블로그 주인만 / 붙지 않음: 올린 사람만. 안 되면 없는 파일과 같은 404. 파일은 `Content-Disposition: attachment; filename*=UTF-8''…`, 사진은 `inline`.
- **FR-008**: 첨부 응답은 `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; img-src 'self'; media-src 'self'; sandbox`, `Cache-Control: private, no-cache`, `ETag: "키"`.
- **FR-009**: `npm run posts:cleanup [-- --dry-run]`이 붙지 않은 지 하루 지난 첨부와 행 없는 1시간 지난 파일을 지운다. 저장 중인 첨부(잠긴 행)는 건너뛴다.
- **FR-010**: 저장소는 서버 디스크 `UPLOAD_DIR`(기본 `storage/uploads`, git 제외)이고, `src/server/storage.ts`만 바꾸면 다른 저장소로 옮길 수 있다.

### Key Entities

- **Attachment**: 키, 올린 회원, 종류(image/file), 원래 이름, 형식, 크기, 붙은 글(없을 수 있음), 떨어진 시각, 올린 시각.

## Success Criteria *(mandatory)*

- **SC-001**: 위 수용 시나리오가 모두 자동 테스트(E2E 또는 단위)로 통과한다.
- **SC-002**: 남의 첨부·비공개 글 첨부·붙지 않은 남의 첨부를 여는 요청 중 성공하는 것이 0건이다.
- **SC-003**: 저장된 본문에 `data:`, 다른 사이트 이미지, DB에 없는 키가 0건이다.
