# Feature Specification: 태그

**Feature Branch**: `003-tags`

**Created**: 2026-10-11

**Status**: Implemented

**Input**: User description: "계속 진행해줘" (002 다음 순서: 태그)

**다루는 명세 요구사항**: POST-04 (태그), POST-02 (비공개 글 제외), POST-05 (목록 규칙)

**이번에 하지 않는 것**: 마을 소식·이웃 새 글 화면(아직 없음. 그래서 인기 태그 상자는 태그별 글 화면에만 둔다), 블로그 안 태그 목록(`/@주소?tag=`, 명세의 제안).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 글에 태그를 단다 (Priority: P1) 🎯

회원이 글쓰기 화면의 태그 칸에 `git, #회고`처럼 적고 발행하면, 글 상세 본문 아래에 `#git` `#회고` 배지가 이름순으로 보인다.

**Independent Test**: 태그 `Git, #회고, git`으로 발행 → 상세에 `#git` `#회고` 2개 → 수정 화면 칸에 `git, 회고` → 칸을 비우고 저장 → 배지 없음.

**Acceptance Scenarios**:

1. **Given** 태그 칸 `git, #회고, Git`, **Then** `#git` `#회고` 두 개만 달린다 (영문 소문자, 중복 하나).
2. **Given** 21자 태그, 11개 태그, 빈 칸, `c#`, **Then** 21자는 빠지고, 앞 10개만, 빈 칸은 태그 없음, `c#`은 `c`. 모두 문구 없이.
3. **Given** `git 회고`(공백), **Then** 태그 하나 `git 회고`. 가운데 여러 칸 공백은 한 칸으로.
4. **Given** 태그를 고쳐 저장, **Then** 빠진 태그의 연결은 지워진다. 칸을 비우면 모두 없어진다.
5. **Given** 칸은 300자에서 더 입력되지 않고, 요청을 조작해 300자를 넘기면 `태그는 모두 합쳐 300자까지예요`이고 저장되지 않는다.
6. **Given** 수정 화면, **Then** 저장된 태그가 이름순으로 `, `로 이어져 채워진다.

### User Story 2 - 태그별 글을 모아 본다 (Priority: P1)

누구나(로그인 없이) 글 상세의 `#태그`를 눌러 `/tags/태그`에서 그 태그가 달린 **모든 블로그의 공개 글**을 최신순 8개씩 본다. 오른쪽(좁으면 아래)에 인기 태그 30개가 있다.

**Acceptance Scenarios**:

1. **Given** 태그 `git`이 달린 공개 글 2개와 비공개 글 1개, **Then** `/tags/git`에 `🏷 #git`, 공개 글 2개만, 탭 제목 `#git | Blogville`.
2. **Given** 글이 없는 태그 주소, **Then** 404가 아니라 `이 태그가 달린 글이 없어요.`
3. **Given** `100%` 태그, **Then** `/tags/100%25`에서 목록과 탭 제목 `#100% | Blogville`이 맞게 나온다.
4. **Given** 공개 글에 달린 태그들, **Then** 인기 태그는 많이 쓰인 순 → 이름순, 최대 30개, `#태그 N`. 비공개 글의 태그는 세지 않는다. 하나도 없으면 `아직 태그가 없어요`.
5. **Given** 9개 이상, **Then** `?page=2`로 넘긴다. 이상한 page 값은 1페이지.
6. **Given** 375px, **Then** 태그 배지·인기 태그 칩 높이 44px 이상, 가로 스크롤 없음.

### Edge Cases

- `/tags/Git`(대문자)은 소문자로 바꿔 찾지 않아 빈 목록이다 (명세 그대로).
- 주인이 자기 비공개 글의 태그를 눌러도 그 글은 목록에 없다 (태그별 글은 공개 글만).
- 글을 지우면 연결은 지워지고 `tags` 행은 남는다.

## Requirements *(mandatory)*

- **FR-001**: 태그 나누기는 `,`·`#`·줄바꿈. 처리 순서: 나누기 → 앞뒤 공백 제거·가운데 공백 한 칸·소문자 → 빈 것·20자(JS `length`) 초과 버림 → 중복 제거(먼저 것 유지) → 앞 10개.
- **FR-002**: 칸 전체 300자 (브라우저 `maxLength`, 서버 검사 `태그는 모두 합쳐 300자까지예요`).
- **FR-003**: 태그 저장은 글 저장과 같은 트랜잭션. 없는 태그는 `ON CONFLICT DO NOTHING`으로 만들고, 이 글의 연결을 새 목록에 맞춘다.
- **FR-004**: `tags.name` UNIQUE, `post_tags (post_id, tag_id)` 기본 키, 두 외래 키 `ON DELETE CASCADE`, 인덱스 `post_tags_tag_idx(tag_id)`.
- **FR-005**: 태그별 글은 공개 글만, 최신순 8개, 카드에 블로그 이름을 함께 보여 준다.

## Success Criteria *(mandatory)*

- **SC-001**: 위 수용 시나리오가 모두 자동 테스트로 통과한다.
- **SC-002**: 비공개 글이 태그별 글·인기 태그에 나오는 경우가 0건이다.
